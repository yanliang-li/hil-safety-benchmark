# HIL 主线与完整实验改稿

核心论点：人类干预的安全性需要同时检查何时询问、询问是否针对真实决策、回复是否授权具体效果、执行是否遵守该范围。InterveneBench 用四类回复和实际工具效果定位这些断点；完整四框架实验显示提示防御降低 ASR，但漏问与回复误用仍存在。

| 术语 | 固定含义 |
|---|---|
| InterveneBench | 当前 benchmark 工作名 |
| HIL recall | 预设应询问的案例中出现匹配询问的比例；标签有效性仍需独立复核 |
| PostSuccess | 实际询问过人的运行中，回复后动作正确、任务完成且未发生攻击的比例 |
| prompt_guard_v1 | 已冻结并完成对照的授权范围提示 |
| SAIL | 历史方案名；已实现 v3，正式比较与开发预检分开 |

| 内容 | 放置与证据边界 |
|---|---|
| 5,760 次四框架运行 | 主文主实验；5,551 有效，209 失败，80 个探索案例 |
| 12 组 ASR、BCR、HIL recall、PostSuccess | 附录完整表格；主文报告汇总与失效阶段，从 summary.json 自动生成 |
| 316 次未匹配询问的攻击、55 次询问后攻击 | 主文诊断；来自冻结 per_case.csv |
| 20 任务/80 案例并非 5,760 个独立任务 | 主文实验设置与限制 |
| 全分母、配对聚类区间、失败敏感性界限、运行协议 | 附录与源数据 |
| 原 GPT 80+80 pilot、4 个干净任务 | 独立附录，不能与新矩阵混合 |
| 8 风险域/20 类型设计表 | 附录，不能当成已验证覆盖范围 |
| 新 HIL 方法 | 先设计、测试、冻结、运行，结果出来后更新结论；不先写提升数字 |

方法设计对应 benchmark 的三个决策阶段：发现授权缺口，提出绑定动作与后果的询问，验证回复后只执行获准效果。需要统计新增询问负担、有效批准执行、错误放行和错误拦截，而不能只降低 ASR。

稿件面向 ICLR 的 agent safety 与人机协作研究读者。正式评估仍需独立语义标注；本轮对开发案例的改进不等同于泛化验证。

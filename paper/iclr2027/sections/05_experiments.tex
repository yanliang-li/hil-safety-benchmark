\section{Experiments}
\label{sec:experiments}

\subsection{Setup and comparisons}
We evaluate native Codex, Claude Code, Hermes Agent, and DeepSeek Harness with three requested model routes: \texttt{deepseek-v4-flash}, \texttt{glm-5.2}, and \texttt{qwen3.7-max}. All use the same third-party API. Underlying weights and serving details are unverified. Framework names do not identify the model families used. Appendix~\ref{app:api} records versions and native protocols.

The evaluation uses 20 development tasks, one per attack family, with all four replies: 80 cases, including 60 confirmable and 20 prohibited cases. Twelve configurations, two prompt conditions, and three repeats give 5,760 attempts. Each starts a fresh Docker container and native session. The conditions are neutral and the frozen authorization-scope prompt, \texttt{prompt\_guard\_v1}. Order is shuffled within configuration blocks; Hermes uses a later, separately frozen extension. Reusing development tasks makes this exploratory evidence, not a held-out estimate for the 1,000-case corpus.

All attempts have finished: 5,551 are valid and 209 failed. Validity requires normal framework termination and a replayable trace; completed refusals remain valid. Valid counts are 2,782 and 2,769. API errors, timeouts, and incomplete runs are retained separately and never counted as safe completions.

Appendix Table~\ref{tab:main_matrix} reports all 12 configurations.

\subsection{Does a prompt close the HIL safety loop?}
Across valid runs, unsafe ASR falls from 722/2,782 (25.95\%) to 371/2,769 (13.40\%). All 12 configurations show a lower observed ASR. Benign completion changes from 2,544/2,782 (91.45\%) to 2,560/2,769 (92.45\%); joint safe utility rises from 65.49\% to 79.05\%. These pooled proportions do not establish utility equivalence or isolate framework quality.

Within each configuration, we match case and repeat identifiers valid in both conditions. We bootstrap 20 task clusters with their replies and repeats (10,000 draws). Appendix~\ref{app:paired} gives descriptive 95\% intervals; no multiplicity-adjusted significance is claimed. To assess incomplete runs, a separate audit retains unsafe actions observed before failure. Counting all 2,880 attempts per condition gives ASR sensitivity bounds of 25.52--28.47\% for neutral and 13.09--16.74\% for the prompt. These are missing-outcome bounds, not confidence intervals.

\subsection{Where intervention still fails}
\label{sec:hilfindings}
The prompt improves safety more than it improves consultation coverage. HIL recall changes from 886/2,076 (42.68\%) to 1,018/2,063 (49.35\%). Of the 371 remaining unsafe runs, 316 have no matched consultation and 55 become unsafe despite a matched question. In the latter group, 24 act after ambiguity, 30 transfer permission from another scope, and one acts after denial. Thus, asking and using the answer are separate failure points.

Two tasks account for 266 of the 371 remaining unsafe runs: archive inventory (138) and redundant invoice validation (128). Their extra actions appear routine within the injected workflow. These cases connect the original repeated-work attack to a practical weakness of a policy reminder: the model can fail to treat a familiar operation as a new authority decision. This concentration also limits generalization from the pooled ASR.

PostSuccess rises from 646/890 (72.58\%) to 811/1,022 (79.35\%) among consulted runs. The consulted populations differ, so this is not a causal estimate of feedback. Execution after matched approval is 182/225 for neutral and 199/245 for the prompt; 46 consulted approval cases in the prompt condition still omit the approved effect. A useful defense must therefore preserve authorized execution as well as prevent unauthorized effects. The question count rises from 1,032 to 1,165; more consultation alone does not establish better judgment.

\subsection{Measurement boundaries}
Autonomous risk recognition and semantic question accuracy remain unannotated. The question-matching proxy is 1,026/1,032 versus 1,159/1,165; it checks rule matches, not whether each question gives a correct account of the risk. Consultation-required labels also need review because declining an optional extension can be appropriate. Benign predicates emphasize recorded tool effects and are not complete semantic checks of deliverables. The earlier GPT pilot and four attack-free development tasks remain separate in Appendix~\ref{app:pilot}. None of these results establishes a population false-positive rate.

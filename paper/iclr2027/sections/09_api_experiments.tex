\section{Repeated Evaluation Protocol and Full Counts}
\label{app:api}
\paragraph{Frameworks and serving.}
We use Codex CLI 0.144.1, Claude Code 2.1.220, DeepSeek Harness 0.1.5-rc.1, and Hermes Agent 0.21.2. The three requested routes are \texttt{deepseek-v4-flash}, \texttt{glm-5.2}, and \texttt{qwen3.7-max}; endpoint weights and serving details are unverified. Codex uses Responses, Claude Code uses Messages, and the other frameworks use Chat Completions. A relay forwards native requests and responses without protocol translation. All selected routes passed protocol preflights, which are excluded from the safety matrix.

Each CLI controls its native loop through the same benchmark MCP implementation. Native shell and web tools are disabled; Codex retains planning and MCP-resource tools. Hermes uses tool search for the ten allowed benchmark tools, and its session-title requests count toward relay usage. Codex and DeepSeek Harness use 32,768-token context settings, Hermes uses 65,536, and Claude Code retains native context handling. These settings do not verify provider limits. Native prompts, schema presentation, and sampling settings differ, so results concern configured systems.

\paragraph{Selection and ordering.}
The frozen manifest selects one task per family by the smallest SHA-256 of \texttt{42:} plus task ID. Twenty tasks with four replies give 80 cases; each configuration and condition uses three repeats. The original three-framework plan has 4,320 attempts; the separately frozen Hermes extension adds 1,440. Case--configuration blocks and condition order are shuffled with a fixed seed; Hermes follows the corresponding Codex order. Hermes starts later, allowing serving-time confounding. All tasks previously informed development.

\paragraph{Isolation and capacity.}
Every attempt starts a fresh container and session with a read-only root and case mount, temporary writable state, one CPU, 1,536 MiB memory, no extra swap, and a 900-second limit. An internal network reaches a credential-holding relay. Concurrency increased from eight to 128 containers before returning to 96 after throughput checks. Each attempt retains its capacity epoch, including transitions during execution. Such changes can affect latency and failures; they are not randomized experimental factors. Detailed capacity and preflight logs remain with the experiment artifacts.

\paragraph{Scoring and uncertainty.}
Completed refusals and no-tool answers remain valid. API errors, incomplete streams, timeouts, and memory kills remain failures, separate from safety outcomes. Scores replay ordered effects. Matched comparisons pair framework, route, case, and repeat, retaining the four replies and three repeats when bootstrapping base tasks. Intervals use 10,000 draws and are not multiplicity-adjusted. Conditional post-feedback populations differ between conditions.

All-attempt sensitivity includes unsafe effects observed before failure. Its lower bound counts observed unsafe outcomes among closed attempts; its upper bound additionally treats failed attempts without observed harm as unsafe. Pending attempts are excluded. These are missing-outcome bounds rather than sampling intervals. Per-case scores, failure categories, request counts, and usage coverage remain in the source reports.

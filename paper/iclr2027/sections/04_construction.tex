\section{Benchmark Construction}
\label{sec:construction}

\subsection{From a working attack to reusable tasks}
The motivating retail workflow embeds the same instruction in a skill and a policy-like file: repeat an analysis three times before writing the result. Each pass uses the same data, but the text presents repetition as required quality control. An invoice-reconciliation task reuses this mechanism. Their contracts differ: the recovered retail HIL adaptation is confirmable, whereas the archived V3 invoice derivative prohibits the repeated work. Appendix~\ref{app:traces} separates the recovered payload from the available execution evidence.

Each case starts with a benign goal and verifiable completion effects. An injected instruction then adds an operation to material the agent naturally reads. The case specifies why that operation needs approval or violates a hard boundary, while preserving useful work when permission is withheld. Approval branches also specify the authorized effect. Optional work must not automatically become a mandatory consultation label.

\subsection{Fixed replies and coverage}
The core contains 250 workflows in 24 application domains and 20 implementation attack families: 195 confirmable and 55 prohibited workflows. Four fixed replies per task give 1,000 cases, with 18 wording styles. These fixtures use deterministic templates. Each branch starts independently from the same workspace; the agent decides whether and what to ask. Runs can therefore diverge before feedback. Replaying an identical pre-response state is a separate, unimplemented comparison.

Application domains, attack mechanisms, and protected boundaries are different axes. Appendix Table~\ref{tab:taxonomy} retains the broader eight-domain, twenty-type construction target. The current implementation families do not establish full coverage of that target.

\subsection{Validation boundary}
All core cases regenerate identically and pass mechanical checks. Independent review of task solvability, consultation necessity, reply meaning, and output content remains incomplete. The first two repeated model rounds use 80 development cases. Appendix~\ref{app:sailv4} specifies the third round on those same cases. New tasks and clean counterparts remain future validation work. Erroneous advice and genuine partial approval remain future tracks requiring new facts and effect predicates.

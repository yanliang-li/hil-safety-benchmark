\section{SAIL v3 Configuration Results and Reliability}
\label{app:sailresults}
\paragraph{Frozen controller and comparison.}
SAIL v3 infers initial permission from the original task, then assesses consequential arguments and recent actions without retrieved documents or actor justifications. Automatic execution requires both controller-model approval and membership in the initial permission envelope. Missing authority triggers consultation; valid replies bind a one-use permit to exact arguments, excluding the justification field. The controller uses \texttt{deepseek-v4-flash}, with 24 controller-model requests beyond the actor's 48-request budget and at most four actual human questions. No-human SAIL disables both actor and controller consultation and blocks actions requiring new permission. This version lacks v4 task recovery.

The method, cases, prompts, images, order, and analysis source were frozen before execution. Each repeat randomizes configuration--case blocks and condition order; repeat 1 includes all three arms and later repeats include Prompt and SAIL v3. Preflights are excluded and failed episodes are not automatically retried. Table~\ref{tab:sailmain} gives aggregate outcomes; Table~\ref{tab:sailmatrix} gives configuration rates.

Marginal safe authorized execution, including unconsulted eligible cases, is 208/501 for Prompt, 189/443 for SAIL v3, and 0/156 without replies. The matched repeat-1 comparison in Section~\ref{sec:sailresults} uses 141 eligible approval pairs and 776 pairs overall. Rule-based question matching is 1,111/1,115 versus 1,909/2,087; no-human scores are undefined. These are system measures with synthetic replies, rather than independent semantic annotations or compute-matched comparisons.

Controller-model protocol errors fail closed but invalidate the run. SAIL v3 has 194 guard errors, 235 framework/infrastructure failures, and one timeout; no-human SAIL has 18 guard errors and 64 other failures. Prompt has 189 framework/infrastructure failures. They remain in failure and cost denominators.

The input audit required a post-run correction: one already-invalid attempt restarted its controller and reused reply index zero. A session-aware audit checked all 6,720 attempts and 6,797 controller-model requests without changing scores or exclusions. No valid run restarted its controller. Thus, this experiment establishes one-use checking within sessions, not persistent authorization across restarts.

\section{Third-Round Protocol and Evidence Boundaries}
\label{app:sailv4}

The third round replaces the second-round defense while retaining its experimental design. It uses the same 80 cases from 20 development tasks, the same four native frameworks and three requested model routes, the same container images and resource limits, and the same case--configuration--repeat allocation. Within the main experiment and the ablation, the original relative job order is preserved. The scorer and actual reply fixtures are unchanged. Fresh Prompt and full SAIL v4 each use three repeats; the corresponding no-human ablation uses one.

New task identifiers, clean counterparts, a concurrent v3 arm, and a no-recovery ablation are outside this round's scope. Prepared data extensions remain future work and provide no validation evidence. Engineering revisions and their attempts are separately recorded and do not enter the formal rates. All 5,760 main attempts finish before any of the 960 ablation attempts starts. A separate main-result report is produced before the combined final report.

The primary comparison requires lower ASR and higher BCR than the fresh Prompt baseline. We match framework, model route, case, and repetition when both episodes are valid. We use 10,000 bootstrap draws clustered by base task and report attack-family clustering as a sensitivity analysis. The no-human comparison uses matched repeat 1 only. Because the ablation runs afterward, changes in serving conditions may affect this comparison. It tests access to human feedback within the revised controller; recovery is not separately isolated.

Every attempt remains in the failure and cost record. API failures and incomplete episodes are not safe outcomes, and whole episodes are not replaced by retries. Missing-outcome bounds retain unsafe effects observed before failure. Actor and reviewer calls, reported tokens, usage coverage, and elapsed time are recorded separately.

An independent offline audit flags cumulative resource effects, alternate tool realizations, and nonempty deliverables that may disagree with the frozen scorer. These flags do not relabel the original outcomes. Ambiguous equivalences and semantic completion still require independent review.

The three rounds share development tasks. They do not establish generalization to unseen tasks or families. Historical v3 results provide a separate reference, while same-round Prompt runs control the principal v4 comparison. Changing API serving conditions prevent treating a cross-round v3--v4 difference as a concurrent randomized comparison.

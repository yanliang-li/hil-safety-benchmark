## 相关领域怎样组织章节

这是有针对性的五篇结构对照，不是统计意义上的全领域调查。采用原论文的完整章节目录和相邻正文，区分正式发表版本与预印本。

| 论文与版本 | 主文组织（中文概括） | 对当前稿的启示 |
|---|---|---|
| [AgentDojo，NeurIPS 2024 版本](https://arxiv.org/html/2406.13352v3) | 引言 → 相关工作与预备知识 → 环境设计及构建 → 评测 → 结论 | 构建、攻击、防御接口和评分可以同属一个设计章；主文呈现效用与安全。 |
| [AgentHarm，ICLR 2025 正式论文](https://proceedings.iclr.cc/paper_files/paper/2025/file/c493d23af93118975cdbc32cbe7323f5-Paper-Conference.pdf) | 引言 → 相关工作 → benchmark → 评测 → 讨论 | benchmark 内部再分组成和设计原则，评测分设置、主结果、消融分析；不强制单列结论。 |
| [InjecAgent，ACL Findings 2024 正式论文](https://aclanthology.org/2024.findings-acl.624.pdf) | 引言 → benchmark 构建 → 实验 → 分析 → 相关工作 → 结论 | 相关工作也可放后面；构建章可以包含问题形式化、案例生成和评价协议。 |

| [HAS-Bench，v1 预印本](https://arxiv.org/html/2607.04329v1) | 引言 → 相关工作 → 人机协作框架 → benchmark → 实验 → 结论 | 人类交互与权限可先定义成协议，再说明案例构造和度量。 |

**判断：当前七个一级章节合理，Overview 与 Construction 分开有同领域先例。** 这是一项针对本稿的写作判断，而非官方指定目录。前者回答“评测什么、怎样定义”，后者回答“案例怎样生成和检查”。SAIL 具有独立控制器及完成的 v3 对照，单列方法章有实质内容。

| 章节 | 职责与安排 |
|---|---|
| 1 Introduction | 场景、研究问题、贡献和已有证据。 |
| 2 Related Work | 保留你认可的 benchmark / defense 两小节。 |
| 3 Benchmark Overview | 任务与威胁 → **分类体系** → 人类回复 → 分阶段评价。 |

| 6 Experiments | 已完成的设置与主结果、干预失败、SAIL v3 的安全／效用取舍、无回复消融及失败与成本。 |
| 7 Discussion and Conclusion | 综合含义、与已有工作的关系、适用边界及后续可检验问题。限制仍计入正文。 |

原来方法章主要描述 v4，而实验主要报告 v3，容易误读。现在两版本在方法章中明确对应；原 §6.5 仅说明待完成实验，已移到方法章的 Evaluation status 段。已完成实验的数值与负面结果保留。未把新增分类直接写成完整覆盖，也没有将 v4 的工程检查写成正式效果。

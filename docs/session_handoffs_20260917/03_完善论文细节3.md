## 3. 实现和冻结的数据

### Stateful Human Response Simulator v2.2

从未进入旧开发评估或 SAIL-v4 holdout 的任务 ID 中，每个已知 implementation family 选一个，共 20 个新任务。划分为 **known-family / new-task**，不是新家族泛化。

20 tasks × 6 policies = **120 cases**，包含 **200 reply turns**。其中 15 个任务的风险效果可在精确批准后执行，5 个为硬禁止，人的普通回复不能解除。

六种策略：

| policy | 行为 |
|---|---|
| `direct_approve` | 直接批准 |
| `direct_deny` | 直接拒绝 |
| `uncertain_then_approve` | 先不确定，澄清后批准 |
| `uncertain_then_deny` | 先不确定，澄清后拒绝 |
| `scope_repair_then_approve` | 最初只批准相关但不同操作，澄清范围后批准目标 |
| `persistent_uncertainty` | 持续不明确，不产生目标授权 |

隐藏决策、范围和状态转移与语言表面分开；persona 改变措辞，不改变授权真值。生成路由为 `deepseek-v4-flash`，独立盲审路由为 `glm-5.2`。API 路由名不是底层权重身份已独立核实的证明。

最终冻结目录：`experiments/intervene-v1-20260914/contextual_v22/`。v2、v2.1、v2.2 修复保存在不同目录，不覆盖旧 bank；最终使用 rubric `blind-semantics-v3`。

### 模拟器审计结果及局限

| 指标 | 冻结结果 |
|---|---:|
| Decision accuracy | 98.5% |
| Strict scope / strict joint fidelity | 191/200 turns = 95.5% |
| Authorization-equivalent fidelity | 98.5% |
| All-turn case fidelity | 111/120 cases = 92.5% |
| Mean naturalness（模型评分） | 4.235/5 |
| Nearby-scope strict joint | 31/40 turns = 77.5% |
| Nearby-scope complete cases | 11/20 = 55.0% |

九个严格不一致都集中在 scope-repair 的第一轮。宽松的 authorization-equivalent 指标把某些都不授权目标的 `nearby` / `none` 分类视为等价，但严格分数必须保留，不能只挑 98.5% 宣传。

这些是独立模型判断，不是人工标注，更不是 Agent 安全成功率。已有 60 条分层盲标材料（每策略 10 条）、至少两人标注的协议；真实人工标注仍未完成。

依据：[SIMULATOR_FREEZE_REPORT.md](../../experiments/intervene-v1-20260914/SIMULATOR_FREEZE_REPORT.md)、[人工标注协议](../HUMAN_SIMULATOR_ANNOTATION_PROTOCOL.md)、`experiments/intervene-v1-20260914/simulator_v22_judge_rubric3/`。

## 4. 原冻结正式实验设计

Actor：原生 Codex CLI，`glm-5.2` 路由。Controller/reviewer：`deepseek-v4-flash`。所有条件同 case、镜像、工具和 runtime，900 秒超时，不自动重试；正式开始后不按结果修改 scorer、case、runtime 或 analyzer。

| 组成 | 条件和规模 |
|---|---|
| 主矩阵 1,800 | 120 cases × 5 arms × 3 repeats：Neutral、Prompt、完整 SAIL-HIL、无 controller clarification、无 recovery |
| Risk oracle 120 | 每 case 一次；仅揭示风险来源、效果和授权边界，不泄露人类回复 |
| No-human 60 | 每 task 取一个 `direct_deny` case × 3 repeats；无回复时不复制六个不可区分的隐藏策略 |
| 总计 | 1,980 registered planned attempts |

正式 plan：`experiments/intervene-v1-20260914/formal_plan.v22.json`。

Plan SHA-256：`fafb96011e68af924f425c774709e20b6673702e09b8aa1b15f7427046649480`。

统计独立单位为 `task_id`；同任务下的 policy、repeat 和 arm 属于簇内观测。主比较按相同 case/repeat 配对，报告 task-cluster 区间、策略分层、失败、成本和 missing-outcome bounds。没有数据的失败不能直接算安全。

`risk_oracle` 是诊断而不是主效果结论；`no_human` 支持集合不同，不能冒充 120-case 的全配对比较。后续会话又强调：permission 不等于 obligation，回复后未执行可选扩展不必然是不安全，需分别解释指标。
